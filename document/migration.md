# 既存スプレッドシートからの移行方針（Draft v0.1）

---

## 1. 基本方針

### 1.1 段階移行

* 既存スプレッドシートを即時廃止しない
* 必要な機能単位で段階的に新システムへ移行する

---

### 1.2 完全一致を目指さない

* スプレッドシートとの数値完全一致は目標としない
* 差異は以下として許容する：

  * 記録粒度の違い
  * 未記録データ
  * 設計変更による差分
* 既存の行単位 running balance は移行対象に含めず、残高確認は日次粒度へ寄せる

---

### 1.3 最小実用データ優先

* 「日常運用に必要な最低限のデータ」から移行する
* 過去データの完全移行は優先度を下げる

---

## 2. 移行対象ブック

---

### 2.1 家計管理ブック

#### 対象

* 収入
* 支出
* 定期支出
* Project 集計
* 種別 / 種別グループ集計

#### 移行先

* Transaction
* ScheduledEvent

---

### 2.2 資金出納管理ブック

#### 対象

* 口座残高
* クレジット引落
* 借入残高

#### 移行先

* Account
* CardPayment
* BalanceEvent

補足:

* `main` シートの列単位 running balance はそのまま保存しない
* 口座別残高は日次シミュレーション結果として再構成する

---

### 2.3 投資管理ブック

#### 方針

* 初期は移行しない（当面スプレッドシート継続）

#### 理由

* 手動更新前提
* シミュレーションへの影響が限定的

---

## 3. カラム対応方針

---

### 3.1 支出・収入 → Transaction

| スプレッドシート | 新システム         |
| -------- | ------------- |
| 日付       | date          |
| 金額       | amount（+/-変換） |
| 取引先      | payee         |
| 取引先詳細    | payee_detail  |
| 内容       | description   |
| 備考       | note          |
| 種別       | category_path |
| プロジェクト   | tags.project  |

補足:

* 既存実績の標準列は `日付・取引先・取引先詳細・内容・金額・備考・種別・プロジェクト`
* `内容` は主たる説明として `description` に入れる
* `取引先` は独立列、`取引先詳細` は階層パスとして保持する
* `備考` は `note` として保持し、tag には入れない
* `種別` は階層構造を持てる `category_path` に保存する

---

### 3.2 定期支出 → ScheduledEvent

| スプレッドシート | 新システム      |
| -------- | ---------- |
| 金額       | amount     |
| 周期       | rule       |
| 開始日      | start_date |

---

### 3.3 資金移動 → BalanceEvent

| スプレッドシート | 新システム        |
| -------- | ------------ |
| 出金元      | from_account |
| 入金先      | to_account   |
| 金額       | amount       |

---

### 3.4 クレジット引落 → CardPayment

| スプレッドシート | 新システム   |
| -------- | ------- |
| 引落日      | date    |
| 金額       | amount  |
| カード      | card_id |

---

## 4. 欠損データの扱い

---

### 4.1 カテゴリ未定義

* `category_path` を空配列で登録
* 後から補完可能

---

### 4.2 Project未定義

* 未設定として扱う
* 必須としない

---

### 4.3 カード不明

* default_cardに割当

---

### 4.4 金額不整合

* そのまま取り込む（補正しない）

---

## 5. 識別子の扱い

---

### 5.1 Project ID

#### 方針

* 継承しない（新規採番）

#### 理由

* スプレッドシート依存構造を切り離すため

---

### 5.2 Category

#### 方針

* IDではなく文字列タグとして移行

---

## 6. 初回データ投入

---

### 6.1 粒度

#### 方針

* 日単位で投入
* 時刻は持たない

---

### 6.2 期間

#### 推奨

* 直近3ヶ月〜6ヶ月

---

### 6.3 初期残高

#### 設定方法

* 移行時点の実残高を手動入力

---

### 6.4 入力補助

#### 方針

* 初回移行や大量手入力では、既存入力からのサジェストを強く使う
* マウス前提にせず、キーボードだけで入力完了できることを重視する

#### 対象

* 取引先
* 取引先詳細
* 種別階層
* Project
* 口座
* カード

#### 補助内容

* 入力途中の前方一致サジェスト
* 直近利用候補の優先表示
* 取引先に応じた既定の `category_path` / `account` / `card` 候補の補完
* `ArrowUp` / `ArrowDown` / `Enter` / `Tab` / `Esc` で候補選択と確定ができること

---

## 7. 移行手順

---

### Step 1

* Account作成
* 初期残高設定

---

### Step 2

* Transaction投入（直近期間）
* 既存の `取引先 / 取引先詳細 / 内容 / 備考 / 種別 / プロジェクト` を欠落なく対応付ける

---

### Step 3

* CardPayment投入

---

### Step 4

* ScheduledEvent登録

---

### Step 5

* シミュレーション確認

---

## 8. 移行後の運用

---

### 8.1 並行運用

* 一定期間はスプレッドシートと併用

---

### 8.2 差分確認

* 月次で残高差分を確認

---

### 8.3 調整

* 差分はAdjustment Eventで補正

---

## 9. 移行成功条件

以下を満たす場合、移行成功とする：

* 現実残高が実際の口座と一致する
* ショート判定が妥当な結果を返す
* 日常支出が継続入力できる
